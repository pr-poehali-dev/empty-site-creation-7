## Шаг 1. Исправления — **✓ готово**

### 1.1. Поиск в приёмке — **✓ готово**

Пик сканером — только по штрихкоду поставщика.

Поле ввода — штрихкод поставщика и номер заказ-наряда, больше ничего.

Заводские штрихкоды убрать из обоих: после правки 1.2 один код стоит на всей позиции, и поиск по нему вернёт случайный товар из десятков.

### 1.2. Заводской штрихкод расходится не по тому полю — **✓ готово**

Сейчас код расходится по товарам с одинаковым техническим наименованием. Таких не бывает: поставщик дописывает в конец слэш с порядковым номером — «.GS Gold Wheels 10 Bl/78», «...Bl/79». На 16 945 строк — 16 945 разных наименований. Поэтому код и лёг на один товар.

Переделать: код расходится по всем товарам с одинаковым красивым именем — товарная группа, бренд и модель вместе. Таких позиций 2 221, группируются верно.

Если тройка пустая — писать только этой единице, иначе код разлетится по всем безымянным.

Старый код, легший не туда, до-проставить разово руками.

### 1.3. Заводской штрихкод в каталоге приёмки — **✓ готово**

Сейчас его не видно нигде, хотя поле заполняется.

В режиме красивых наименований — в строке позиции, рядом с наименованием. Код у всей позиции общий, один на строку. Сервер в этом режиме отдаёт только название, количество и цену — добавить к ним код. Если внутри позиции коды разошлись — показать пометку вместо кода, чтобы расхождение было видно.

В режиме технических наименований — колонкой в конец таблицы.

### 1.4. Склады — **✓ готово**

Остатки перестроить на красивые имена: строка — позиция с количеством, тап разворачивает товары внутри, ещё тап по товару — его данные и история.

Поиск по складам расширить: модель, бренд, товарная группа, штрихкод поставщика, заказ-наряд, заводской штрихкод. Заводской здесь остаётся — на складе это готовая продукция, поиск по модели там и нужен.

### 1.5. Поправить описания — **✓ готово**

Шестой и седьмой шаги описывают то, что оказалось неверным, и подают это как удачное решение.

Шаг 6: «код проставляется всем единицам с тем же техническим наименованием» — не работает.

Шаг 7: раздел «Учёт по техническим наименованиям» и фраза «красивое наименование в учёте не участвует» — становится наоборот.

В обоих — грабли про слэш с номером от поставщика.

Пятый шаг здесь не трогаем: про поиск по штрихкоду и заказ-наряду там написано правильно.

## Шаг 2. Просмотр закрытой приёмки — **✓ готово**

Сделано: экран `/admin/receiving-archive/:id`, возврат со складов, подтверждение «Закончить».

**Входа с экрана пока нет** — приёмка открывается только по прямой ссылке. Кнопки появятся в шагах 3 и 4 вместе со списками.


Тап по приёмке открывает её как есть:

- сканер выключен, кнопки «Закончить» нет;
- в шапке видно: закрыта, дата, вид, сотрудник;
- четыре счётчика по исходам;
- список проверенного развёрнут — в закрытой он для чтения, а не для контроля последнего пика;
- тап по единице показывает итог проверки без возможности править.

Единственный ввод на экране — поиск товара внутри этой приёмки.

Возврата для правки нет и не будет. Зайти и посмотреть, что делал, — можно.

Сюда же две мелочи:

**Возврат со складов.** Из приёмки жмёшь склад — уходишь на остатки, а стрелка назад кидает в корень приёмок, работа теряется. Должна возвращать в ту же приёмку, сразу в рабочий режим, без вопроса «продолжить или создать новую». Зашёл на склады из меню — поведение прежнее.

**Кнопка «Закончить».** Сейчас закрывает молча, одним тапом. Поставить подтверждение: проверено единиц столько-то, после закрытия приёмка уйдёт в архив, дописать товар будет нельзя, останется непроверенное — открывать новую.

## Шаг 5. Удаление пустых приёмок — **✓ готово**

Пока пробовали приёмку, наплодили пустых записей — они портят вид списка. Из 12 приёмок 11 оказались без единого товара.

**Правило простое: есть товар — приёмка остаётся навсегда, товара нет — это мусор, его можно убрать.**

Три условия, все обязательны:
- приёмка **закрыта** — открытая это работа прямо сейчас;
- **товаров ноль**;
- приёмка **своя**, либо удаляет владелец.

Отдельного права не заводили: удаляет владелец или сам мастер свою. Чужую не удалит даже тот, кто вправе её видеть — смотреть и стирать разные вещи.

Условия проверяются на сервере в момент удаления, а не по тому, что прислал экран: пока список висел открытым, в приёмку могли дописать товар. Кнопка показывается только там, где сервер и правда удалит — признак приходит с сервера вместе со строкой.

Кнопка в трёх местах: в шапке открытой на просмотр приёмки и в строках обоих списков — «Мои прошлые приёмки» и общий «Список приёмок». В строке отдельной кнопкой, не по тапу, чтобы не стереть вместо открытия.

Строка приёмки вынесена в общий компонент `ReceivingRowItem` — до этого она дублировалась в двух списках.

В базе новая колонка `auto_closed` и индекс по открытым приёмкам.

## Решённые вопросы — чтобы не всплыли снова

**Заводской штрихкод не годится для поиска товара.** Он общий на всю позицию: одно сканирование закрывает модель целиком. Искать по нему единицу бессмысленно — вернётся случайная из десятков. Индивидуален только штрихкод поставщика. На складах — исключение: там готовая продукция, и поиск по модели как раз нужен.

**Техническое наименование не годится для группировки.** Поставщик дописывает слэш с порядковым номером, все 16 945 наименований разные. Группировать только по тройке: товарная группа, бренд, модель — 2 221 позиция.

**Заказ-наряд сканером не пикается.** У него нет штрихкода. Только в поле ввода, руками.

## Отложено, но не выброшено

**Модалка проверки висит без ограничения по времени.** Пока она открыта, сканер молчит. Мастер отвлёкся с открытой карточкой, потом пикает следующий товар — ничего не происходит, система ждёт решения по предыдущему. Человек думает, что сканер сломался. Кандидат на автозакрытие по бездействию с возвратом сканера в работу.

**Создание ненайденной единицы.** Обещано в пятом шаге, не сделано. Товара нет в загрузках — мастер видит код и пояснение, но завести карточку не может. Молча терять нельзя: это предъявлять поставщику.

**Права на список приёмок.** Кнопка «Список приёмок» сейчас открыта всем мастерам, а право `see_all_lists` лишь добавляет чужие приёмки. Владелец просил иначе: отдельное право, и без него в раздел не попасть даже по прямой ссылке. Обсуждение отложено, решение не принято.

**Удаление пустых открытых приёмок** — сейчас нельзя, надо сначала закончить. После автозакрытия (шаг 7) вопрос почти снят: открытой остаётся только сегодняшняя.

**Выгрузка списка приёмок в файл** — не обсуждали.

**Фильтр по сотруднику в общем списке** — фильтр по виду приёмки сделан в шаге 4, по конкретному сотруднику пока нет.

**Поиск по серийному номеру** — решено не брать: пустой у 2 036 строк, среди заполненных повторы.
