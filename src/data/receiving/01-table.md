# Шаг 1. Таблица приёмки

## Задача шага

Создать в базе хранилище, куда лягут все строки из файлов поставщиков. Это основа всего: из неё идёт приёмка, из неё собираются красивые наименования, по ней считаются остатки на складах.

Одна строка таблицы = **одна физическая единица товара**. Не позиция каталога, а конкретный чайник с конкретным штрихкодом.

## Поля из файла поставщика

Заполняются при загрузке, дальше не меняются:

| Поле | Что это |
|---|---|
| Штрихкод | Ключ единицы. Уникален, повтор не допускается |
| Техническое наименование | `.Кофеварка JVC JK-CF34/19` — из колонки «Новое наименование» |
| Серийный номер | Может быть пустым, может повторяться |
| Заявленный дефект | Из колонки «Описание» — что было с товаром до ремонта |
| Бренд | |
| Модель | |
| Товарная группа | |
| Направление | Категория для каталога |
| Номер заказ-наряда | Уникален, второй способ поиска |
| Код товара | Внутренний код поставщика, уникален |
| Вес брутто | |
| Вес нетто | |
| Объём | |
| Цена | Одно поле. Какую колонку файла в него класть — решается при сопоставлении |

## Поля проверки

Пустые до тех пор, пока мастер не проверит товар. Заполняются на шаге 6, **по каждой единице отдельно**:

| Поле | Что это |
|---|---|
| Исход проверки | На продажу / на протирку / не работает / утиль |
| Упаковка | Есть или нет |
| Вес для накладной | Брутто при упаковке, нетто без неё |
| Заявленный дефект подтвердился | Да / нет |
| Новый дефект | Да / нет |
| Описание нового дефекта | Текст от мастера |
| Кто проверял | Сотрудник |
| Когда проверял | Дата и время |
| Номер дневной приёмки | К какой приёмке относится |

Зачем это в карточке каждой единицы: поставщик заявил товар рабочим. Значит ему предъявляем — списком по техническим наименованиям, где по каждой единице видно, что заявляли и что оказалось на деле.

## Служебные поля

| Поле | Что это |
|---|---|
| Текущий склад | СГП / Протирка / Под ремонт / Утиль. Пусто до проверки |
| Из какого файла | Имя загруженного файла |
| Когда загружена | Дата загрузки |
| Поставщик | М-Видео и далее другие |

## Защита от повторной загрузки

Штрихкод в таблице уникален. Если в новом файле встретится штрихкод, который уже есть, строка **не создаётся заново** — система покажет предупреждение и посчитает такие строки отдельно. Так один и тот же файл, загруженный дважды, не раздует таблицу.
