# Общее — приёмка товара

## Зачем всё это

Приходит товар от поставщика большими партиями — счёт идёт на тысячи единиц. Поставщик заявляет товар как рабочий, прошедший через его сервис, но по факту значительная часть оказывается браком. Проверять надо руками, каждую единицу, и результат проверки потом предъявлять поставщику.

Сейчас этого учёта нет вообще: были просто списки товаров, без количеств и без движения. Теперь вводим настоящий учёт — сколько чего и на каком складе лежит.

Работа идёт **с телефона**, прямо в цеху, со сканером в руках. Всё, что делаем, должно быть удобно на маленьком экране — это не пожелание, а основное условие.

## Виды приёмки

Пока три, список расширяемый:

1. **Приёмка рабочего товара без проверки** — товар принимается как есть, по документам.
2. **Приёмка рабочего товара с проверкой** — основной и самый сложный случай. Каждая единица проверяется мастером, результат фиксируется.
3. **Приёмка товара под ремонт** — товар заведомо нерабочий, идёт в ремонт.

Каждый вид доступен не всем: владелец галочками решает, кто какую приёмку видит.

## Два каталога

**Существующий каталог** делался для Беларуси, цены в белорусских рублях.

**Каталог приёмки** — новый, для России, цены в российских рублях.

Пока живут отдельно, что-то будем перекидывать из приёмки в основной. В дальнейшем сольём в один: цены в российских рублях, для остальных стран пересчёт по текущему курсу или по зафиксированному.

## Два вида наименований

Ключевая идея всей системы.

**Техническое наименование** — то, что в файле поставщика: `.Кофеварка JVC JK-CF34/19`. С точкой впереди и номером в конце. Уродливое, но уникальное для каждой единицы товара.

**Красивое наименование** — собирается из трёх колонок файла: `товарная группа + бренд + модель`. Например `Электрочайник Hi EK-18S03`. Годится для каталога и для показа оптовику.

Правило:

- **Учёт, движение по складам и списание — только по техническим наименованиям.**
- **Каталог, списки для оптовиков и накладные — по красивым.**

Красивые повторяются: одна и та же модель приходит десятками штук. В каталог такое имя попадает **один раз**, без дублей, а количество считается по техническим.

Накладная оптовику — красивые имена с общим количеством. Документ списания — технические, поштучно.

## Разбор файла поставщика

Первый файл: М-Видео, лист `Orca Scan`, **16 945 строк, 26 колонок**.

### Что нашли в данных

**Штрихкод уникален во всех 16 945 строках.** Это настоящий ключ единицы товара — по нему сканируем при приёмке и по нему же ловим повторную загрузку.

**Номер заказ-наряда и код товара тоже уникальны.** Годятся как второй способ найти товар.

**Серийный номер ключом быть не может.** Пустой (`NULL`) у 2 036 строк, а среди заполненных 14 909 значений только 11 302 разных — то есть встречаются повторы. Для поиска при проверке не используем.

**Колонка «Кондиция» вопреки названию содержит не состояние товара, а короткое имя** — `ЭЧ HI EK-18S03`. Ещё одно короткое имя лежит в колонке «Наименование». Обе дублируют друг друга и пользы не несут.

**Красивых наименований получается 2 221** из 16 945 строк — то есть в каталог приёмки уйдёт чуть больше двух тысяч позиций вместо семнадцати тысяч.

**Направление — 39 значений**: Пылесосы (5 594 строки), Кухонная техника (2 995), Уход за одеждой (1 912), Климат Зима, Климат Лето и так далее. Это готовая категория каталога для оптовиков.

### Колонки, которые берём

| Колонка файла | Зачем |
|---|---|
| Barcode | Ключ единицы, сканирование при приёмке |
| Новое наименование | Техническое имя, складской учёт и списание |
| Сер.№ | Справочно, ключом не является |
| Описание | Заявленный поставщиком дефект |
| Бренд | Часть красивого имени, фильтр в сводках |
| Модель | Часть красивого имени |
| Товарная группа | Часть красивого имени |
| Направление | Категория каталога приёмки |
| № заказ-наряда | Второй способ поиска при проверке |
| Код товара | Внутренний код поставщика, уникален |
| Брутто, кг | Вес для накладной, если товар в упаковке |
| Нетто, кг | Вес для накладной, если без упаковки |
| Объём, куб.м. | Расчёт объёма поставки |
| Цена | Одна колонка цены в таблице |

Про цену: в таблице приёмки **одно поле цены**. В файле цен две — «Цена» и «Конд. цена», смысл второй пока не выяснен. Какую из них положить в наше поле, решаем при сопоставлении колонок.

### Колонки, которые не берём

Скидка, Дата оформления, Наименование, Кондиция, Место размещения, Адрес ячейки, Код упаковки, Талон, Конечная цена, КОД АТ, Проверка штрихкода.

Причины: часть — внутренняя кухня склада поставщика (место, ячейка, код упаковки — последние два пустые в 5 206 строках), часть пуста целиком (конечная цена — все 16 945 строк) или почти целиком (КОД АТ — пусто в 16 920 из 16 945), часть содержит одно значение на весь файл (Талон — везде «Отсутствует», Проверка штрихкода — одна фраза).

## Файл может быть любым

Формат М-Видео — только первый. Следующий поставщик пришлёт что-то своё, с другими названиями колонок и другим порядком. Поэтому колонки не зашиваем: при загрузке показываем, что нашли в файле, и даём сопоставить с нашими полями руками. Схема запоминается под именем поставщика, второй файл того же вида разбирается сам.

Механизм такой же, как в загрузке счетов.

## Склады

Вводим четыре:

- **СГП** — склад готовой продукции, проверенное рабочее
- **Протирка** — рабочее, но требует чистки
- **Под ремонт** — не работает
- **Утиль** — не подлежит восстановлению

Остатки считаются по техническим наименованиям. Между складами настраиваем перемещение. Отпускать будем с двух складов — СГП и Под ремонт.

## Права

Отдельный раздел внутри «Приёмок». Галочками настраивается для роли целиком или для конкретного человека поверх роли:

- какие виды приёмки доступны
- можно ли грузить файлы
- какие склады видны
- чьи списки видны — свои или всех сотрудников
- в каком виде показывать списки: красивые имена, технические или оба
- доступен ли переключатель каталога при составлении заявки

## Порядок работы

1. Владелец (или тот, кому разрешено) грузит файл поставщика → строки попадают в таблицу приёмки
2. Когда удобно — собирает красивые наименования и заливает их в каталог приёмки
3. Сотрудник открывает приёмку, выбирает доступный ему вид
4. Сканирует товар, видит заявленный дефект, проверяет, определяет исход
5. Товар уходит на свой склад, данные проверки пишутся в его карточку
6. Из складов собираются заявки оптовикам, отгрузка списывает остатки
7. По итогам — сводки: по сотруднику, по отделу, по поставщику для претензии

Приёмка **не ждёт каталог**: она идёт по техническим наименованиям, а красивые можно залить в любой момент.
