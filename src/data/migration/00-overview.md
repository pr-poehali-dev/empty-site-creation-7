# Архивация и перенос сайта — общее

## Цель

Полная резервная копия сайта, по которой его можно поднять **в другом месте** — на своём VPS — и он будет работать: с данными, структурой базы, файлами, функциями, ботом и обменом с 1С.

Плюс — обновление уже работающего сайта на VPS новым кодом без потери данных.

## Схема после переезда

| Где | Роль | Данные |
|---|---|---|
| **VPS** | **Рабочий сайт.** Сотрудники, бот Телеграма, 1С, автокопии на Яндекс Диск | Настоящие, главные |
| **Поехали** | **Мастерская.** Доработки и тесты | Тестовые |

- Код и структура базы идут **отсюда → на VPS** (обновление).
- Данные живут на VPS и **никогда не перезаписываются** обычным обновлением.
- Данные можно по желанию загрузить **с VPS → сюда** для тестов. Только в эту сторону.
- Никаких переключателей «роли» в коде нет. Решили переехать — значит рабочий сайт на VPS.

## Комплект копии

| № | Архив | Что внутри | Откуда берётся |
|---|---|---|---|
| 1 | **База** | Структура таблиц, связи, индексы, все данные | Кнопка на странице «Архивация данных» |
| 2 | **Файлы** | Фото каталога и лотов, файлы от Юры, накладные | Та же кнопка |
| 3 | **Паспорт** | Список секретов (без значений), старый домен, что менять при переносе, контрольные суммы, дата | Та же кнопка |
| 4 | **Код** | Исходники сайта и всех функций, изменения базы | **Только вручную:** ЛК поехали → «Скачать → Скачать код» |
| 5 | **Установщик** | Страница восстановления/обновления и всё для запуска на сервере | Кнопка на странице «Архивация данных» |
| + | **ИНСТРУКЦИЯ ПО ВОССТАНОВЛЕНИЮ.txt** | Пошагово, простым языком | Кладётся в каждый комплект |

Сайт **сам свой код сохранить не может** — у работающего сайта на руках только собранная версия, исходников нет. Поэтому код — только из ЛК поехали.

Каждая копия хранится на сервере сайта и **дублируется на Яндекс Диск** в папку `Резервные копии/ГГГГ-ММ-ДД_ЧЧ-ММ/`.

## Принятые решения

- **Хостинг для переноса — VPS** (Ubuntu, 1–2 ГБ памяти, от 300–500 ₽/мес). Обычный PHP-хостинг не подходит: на нём не запустить функции и PostgreSQL.
- **Код — без GitHub**, через «Скачать → Скачать код». Страница архивации напоминает, если код на Диске устарел.
- **Значения секретов никогда не попадают в архивы и на Диск.** Хранить их отдельно (менеджер паролей).
- **Сервер ставится одной командой** в консоли VPS, дальше всё в браузере.
- **Кириллический домен** переводится в техническое имя автоматически: «склад.рф» → `xn--80aqu2ab.xn--p1ai`.
- **Посредник для Телеграма** на VPS — включается/выключается, обычно не нужен.

- База: 71 таблица, ~82 тыс. строк, 18 МБ данных + 16 МБ индексов, 63 счётчика.
- Код: 613 файлов, 6,3 МБ (сжато ~2,7 МБ). 45 функций, 148 изменений базы.
- Файлы в хранилище: ~1,1 МБ (14 файлов Юры, 2 фото лотов, фото каталога пока нет). Одна запись о накладной ссылается на несуществующий файл.
- Полная копия — ~6–7 МБ, 30 копий — ~200 МБ.
- Текущая архивация копирует **только данные базы**: без структуры, без файлов, без кода.
- Последняя копия — **11.07.2026** (46 таблиц, 45 тыс. строк). Автокопирование **выключено**.
- Восстановление сейчас опасно: таблицы, которых нет в копии, не очищаются — получается смесь старых и новых данных.

## Привязки к платформе, найденные в коде

| Что | Где | При переносе |
|---|---|---|
| Адреса функций `functions.poehali.dev` | 55 файлов страниц, 4 функции | → `https://домен/api/имя-функции` |
| Хранилище `bucket.poehali.dev` | 6 функций | → хранилище на самом VPS |
| Ссылки на файлы `cdn.poehali.dev` | 5 файлов + записи в базе | → новый домен |
| Посредник Телеграма (`tg_proxy_key`, tg-relay) | функции бота | вкл/выкл |
| Расписание (планировщик, автокопии) | настройки платформы | → расписание на VPS |
| Адрес сайта для бота (`WEBAPP_BASE_URL`, `TMA_BASE_URL`) | секреты, бот | → новый домен, бот переподключается |
| Яндекс Метрика | страницы | вручную, новый домен в Метрике |

## Секреты проекта

- **Телеграм:** `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET`, `WEBAPP_BASE_URL`.
- **1С:** `EXCHANGE_API_KEY`; OData — `ODATA_URL`, `ODATA_USER`, `ODATA_PASSWORD` (Трейд-Ресурс), те же с `_FOMKIN` и `_MIRTEH` (не заполнены).
- **Планировщик:** `SCHEDULER_SECRET`.
- **Яндекс Диск:** ключ доступа (появится на этапе 2).
- **Создаются на VPS сами:** `DATABASE_URL`, `MAIN_DB_SCHEMA`, ключи хранилища.

## Мастерская после переезда

Один раз при переезде, через секреты и настройки:

- **Отдельный тестовый бот** — один бот не может работать на двух сайтах.
- **1С** отключить или подключить тестовую базу.
- **Рассылки и планировщик** здесь выключить.

## Как работаем

1. Открываем вкладку этапа, обсуждаем. Юра записывает **План** и ждёт «делай».
2. Юра делает и записывает в **Сделано**, что и как.
3. Владелец проверяет. Найденное — в **Проверка**, исправления — туда же.
4. Этап получает ✓ в названии вкладки, идём дальше.

## Порядок этапов

1. Полная копия
2. Яндекс Диск
3. Восстановление здесь
4. Переходник функций
5. Замена привязок
6. Установщик и обновление
7. Секреты
8. Инструкция-файл
9. Проверка

Этапы 1–3 полезны уже сейчас, даже без переезда.
