# Ценовой стол (этап 1, 31.10.2026)

Страница `/admin/price-desk/:id` (список наборов — `/admin/price-desk`). Только владелец.

## Откуда список
- Заявка → шапка → кнопка с иконкой BadgeDollarSign (только владелец, только сохранённая заявка).
- Создаётся «набор» (`price_sets` + `price_set_items`), source_type='order', source_id=id заявки.
  Повторное нажатие на ту же заявку пересобирает тот же набор (бренд/модель новых товаров сохраняются).
- Новые товары (строки заявки с temp_product_id; у них product_id=19 — заглушка) идут отдельной группой
  в конце. Бренд/модель берутся из temp_products (brand, article), правка хранится только в наборе.

## Разбор
- Серверная часть — `backend/search-dicts/desk.py`, вызов `?section=desk` (лимит 50 функций — отдельную
  функцию создать нельзя).
- Бренд ищется в наименовании по справочнику `search_brands`; если нет — берётся `products.brand`
  (бренд карточки, считаем что он стоит перед моделью), затем папка `product_group`, если её название есть
  в наименовании. Новые бренды заводятся в справочник автоматически.
- Если модель не нашлась, но артикул карточки есть в наименовании — модель = артикул
  (кириллица-двойники → латиница: «КТ-2009» → «KT-2009»).
- Результат сразу пишется в карточку (`search_group_id, search_brand_id, model, feature, parse_status`).
  `manual` никогда не перезаписывается. Ручная правка в ячейке → `parse_status='manual'`.
- Кнопка «Разобрать неразобранные» трогает только parse_status='none'; кнопка в строке — перезапускает разбор
  для одного товара (кроме manual).

## Цены маркетплейсов
- Та же `market-prices`, ключ — бренд+модель (`model_market_prices`), общие с каталогом приёмки.
- Ячейки как в технических: «Все сайты» в строке, отдельный поиск по каждому сайту, «Не тот товар», «Цена верная».
- Колонки «Средняя РФ / РБ» = total_ru / total_by (ручной ввод возможен).
- Новое: `market_price_history` — каждый поиск (сайт, статус, цена, ссылка, кто, когда). Видна в окне ячейки
  цены (и в приёмке тоже), action=history.

## Этап 2: курс, процент, итоговые цены, Excel
- Панель над таблицей: «За 100 RUB — … BYN» (price_sets.rate_by_per_100_rub), «Процент от Базовой, %»
  (price_sets.percent_of_base, можно с минусом, > −100). Сохраняются при уходе с поля (action=rate / percent).
- «Рассчитать цены» (action=calc): Цена РБ = Базовая × (1 + %/100), до копеек; Цена РФ = Цена РБ × 100 / курс,
  до рубля. Ручные не трогает; если есть ручные — вопрос «Пересчитать и ручные?» (include_manual).
  Без курса или процента кнопка неактивна.
- Колонки «Цена РБ, BYN» и «Цена РФ, RUB» после «Базовая сейчас» (price_set_items.price_by / price_ru,
  флаги price_by_manual / price_ru_manual). Клик — ручная правка (action=price), крестик или пустое значение —
  снять «вручную» и вернуть формулу. Ручная РБ → РФ пересчитывается по курсу, если РФ не ручная, и наоборот
  (РБ из РФ — только если у товара нет Базовой).
- Новые товары и товары без Базовой: цены только вручную.
- Внизу итоги с учётом количества и число товаров без цены.
- «Скачать Excel»: наименование, артикул, количество, Цена РФ, Цена РБ; вверху курс, процент, дата.
- Повторное нажатие значка в заявке собирает список заново — курс и процент остаются, цены РФ/РБ этого списка пропадут.

## Этап 3: новая Базовая, приоритет цены с парсинга, цены из 1С закрыты
- Обмен с 1С (1c-exchange, action=products): цены больше не записываются (PRICES_FROM_1C = False).
  Товары, артикулы, бренды, штрихкоды, картинки — как раньше. На странице «Обмен с 1С» надпись.
- products.price_base_parsed — метка «цена с парсинга», ставит только ценовой стол при записи Базовой.
  Заменить такую цену можно: вручную в карточке (метка снимается), снова ценовым столом, или в шаге «Цены»
  загрузки счетов галочкой «Заменить и цены с парсинга» (force_parsed). Без галочки — пропуск,
  «пропущено N — цена с парсинга». Загрузка в каталог (catalog-parse) такие цены всегда пропускает.
- Ценовой стол: колонка «Новая Базовая, BYN» (price_set_items.new_base / new_base_source: avg_by|avg_ru|manual).
  «из средней РБ» — как есть; «из средней РФ» — RUB × курс / 100 (без курса нельзя). Только в пустые ячейки.
  «Рассчитать цены» считает от Новой Базовой, если она есть.
- «Записать Базовую цену»: окно (всего / заменится / впервые / разница > 30%) → products.price_base,
  price_base_parsed = TRUE, история, Новая Базовая очищается. Новые товары не пишутся.
- price_base_history: старая/новая, source (desk_avg_by, desk_avg_ru, desk_manual, card, invoice,
  invoice_revert, catalog_upload), курс, ценовой стол, черновик, кто, когда. Блок «История Базовой цены»
  в окне товара каталога (владелец), section=base_history.
