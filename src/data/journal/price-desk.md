# Ценовой стол (этап 1, 31.10.2026)

Страница `/admin/price-desk/:id` (список наборов — `/admin/price-desk`). Только владелец.

## Откуда список
- Заявка → шапка → кнопка с иконкой BadgeDollarSign (только владелец, только сохранённая заявка).
- Создаётся «набор» (`price_sets` + `price_set_items`), source_type='order', source_id=id заявки.
  Повторное нажатие на ту же заявку пересобирает тот же набор (бренд/модель новых товаров сохраняются).
- Новые товары (строки заявки с temp_product_id; у них product_id=19 — заглушка) идут отдельной группой
  в конце. Бренд/модель берутся из temp_products (brand, article), правка хранится только в наборе.

## Разбор
- Серверная часть — `backend/search-dicts/desk.py`, вызов `?section=desk` (лимит 50 функций — отдельную
  функцию создать нельзя).
- Бренд ищется в наименовании по справочнику `search_brands`; если нет — берётся `products.brand`
  (бренд карточки, считаем что он стоит перед моделью), затем папка `product_group`, если её название есть
  в наименовании. Новые бренды заводятся в справочник автоматически.
- Если модель не нашлась, но артикул карточки есть в наименовании — модель = артикул
  (кириллица-двойники → латиница: «КТ-2009» → «KT-2009»).
- Результат сразу пишется в карточку (`search_group_id, search_brand_id, model, feature, parse_status`).
  `manual` никогда не перезаписывается. Ручная правка в ячейке → `parse_status='manual'`.
- Кнопка «Разобрать неразобранные» трогает только parse_status='none'; кнопка в строке — перезапускает разбор
  для одного товара (кроме manual).

## Цены маркетплейсов
- Та же `market-prices`, ключ — бренд+модель (`model_market_prices`), общие с каталогом приёмки.
- Ячейки как в технических: «Все сайты» в строке, отдельный поиск по каждому сайту, «Не тот товар», «Цена верная».
- Колонки «Средняя РФ / РБ» = total_ru / total_by (ручной ввод возможен).
- Новое: `market_price_history` — каждый поиск (сайт, статус, цена, ссылка, кто, когда). Видна в окне ячейки
  цены (и в приёмке тоже), action=history.
