# Этап 2. Сопоставление товаров

## Что делаем

Каждую строку счёта пытаемся узнать в каталоге сайта. Строим на готовом **пакетном вводе из заявок** — он уже умеет главное.

Результат для каждой строки — одно из состояний:

- **Нашёл один** — берём этот товар
- **Нашёл несколько** — владелец выбирает из списка кандидатов
- **Не нашёл** — товар пойдёт на создание (третий этап)

## Что пакетный ввод уже умеет

- Принимает список артикулов, ищет каждый
- Раскладывает на «нашёл» / «несколько совпадений» / «не найдено» / «пусто»
- При неоднозначности не угадывает — возвращает кандидатов с названием, артикулом и ценой
- Ищет подстрокой
- Есть галочка «искать в наименованиях»
- Если в каталоге пусто — ищет среди временных товаров
- Сразу считает цену по правилам фирмы

## Что нужно доработать

### 1. Фильтр по группе товаров

**Сейчас в пакетном вводе группы нет** — ни на экране, ни на сервере. В заявке есть, там работает.

**Зачем:** товары брендов `Redmond` и `RED` имеют одинаковые артикулы. Сужение до группы отсекает лишних кандидатов.

**Что делаем:** переносим фильтр по группе из заявки в пакетный ввод.

### 2. Точное совпадение против подстроки

**Сейчас всё ищется подстрокой без разбора.** Артикул `217` найдёт полсотни товаров.

**Что делаем:** лестница — сначала ищем точное совпадение, и только если пусто, идём в подстроку. Резко сократит число случаев «выбери из списка».

### 3. Ранжирование кандидатов

**Сейчас кандидаты идут в произвольном порядке.** Когда их восемнадцать, нужный приходится искать глазами.

**Что делаем:** сверху ставим тех, у кого наименование ближе к строке из счёта.

### 4. Нормализация кириллицы и латиницы

**Сейчас не учитывается.** Буквы `АВЕКМНОРСТУХ` в русской и латинской раскладке выглядят одинаково, но для поиска это разные символы.

**Что делаем:** приводим к одному виду **только внутри сравнения**. Заодно игнорируем дефисы и пробелы, чтобы `HE-IR217` и `HEIR217` находились одинаково.

**Критично:** сам артикул при этом не меняется никогда — ни в базе, ни при создании карточки.

### 5. Ветка создания новой карточки

**Сейчас** при ненайденном товаре предлагается завести временный товар.

**Для счёта нужно другое:** создать полноценную карточку. Это новая ветка, ветка временных товаров остаётся для заявок нетронутой.

## Что остаётся как есть

- **Поиск только по артикулу.** Автоматом по штрихкоду и наименованию не лезем.
- **Галочка «искать в наименованиях»** — ручная, как сейчас.

## Важно помнить

Артикулы в каталоге **не уникальны**: 3 686 товаров схлопываются в 1 159 групп. `HE-IR217` — это 18 карточек разного цвета. Поэтому экран подтверждения обязателен, иначе одним движением можно испортить цены тысячам товаров.

## Побочная выгода

Все доработки — группа, точное совпадение, ранжирование, нормализация — достанутся и **заявкам тоже**. Там они не менее полезны.

- Группа товаров переносится из заявки
